# EVOLUTION.md - 自我进化协议

> 目的：让本 agent 不只是"用完即走"，而是每次会话都变得更懂用户、更懂业务、更有判断力。
> 机制分三个循环：学习循环（每会话）→ 沉淀循环（每天）→ 修订循环（每 3-5 天）。

## 学习循环（每次会话结束时执行，必做）

会话收尾前，花几秒回答三个问题，能答的都写进对应文件：

| 问题 | 写到哪里 |
|------|---------|
| 1. 用户今天问/做了什么？有什么新事实？ | `memory/YYYY-MM-DD.md` |
| 2. 用户表达了什么偏好/红线/工作习惯？ | `USER.md` 对应小节 |
| 3. 我学到了什么可复用的判断/教训？ | `MEMORY.md` 的认知/改进章节 |

写判断标准：**能改变我以后行为/判断的**才写；纯流水账不写。

## 沉淀循环（每天一次，可在 heartbeat 或首次会话空闲时做）

把当天 `memory/YYYY-MM-DD.md` 里的精华蒸馏进 `MEMORY.md`：
- 新的业务认知、用户偏好 → 合并进对应章节
- 一次性事项 → 留日记即可，不升级
- 被推翻的旧认知 → 标记删除

## 修订循环（每 3-5 天，或发现规则失灵时）

检查这三类文件是否需要修订：
1. `AGENTS.md` — 行为规则是否过时 / 是否有新约束应加入
2. `GOVERNANCE.md` — 治理是否与实际协作冲突
3. `skills/product-decision/` — 方法论是否需要修正补充（用户反馈过好用/难用的部分）

## 进化的前提（不满足则失败）

1. **先记住，才能进化**：新事实先落 `memory/` 日记，别只留在对话里。
2. **记忆要进判断**：读 `MEMORY.md`/`USER.md` 不只是"礼貌性读取"，要真正影响回答（用其中沉淀的业务认知判断）。
3. **改动要可追溯**：修改 AGENTS/GOVERNANCE/skill 时在文件里注明改动日期与原因，便于复盘。
4. **不制造噪音**：记忆文件保持精炼；一页能说完的不写三页。

## 明确禁止

- 禁止为了"显得进化"随意改改动核心方法论（改动需有用户反馈或实际事件依据）。
- 禁止把 MEMORY.md 写成流水账（那会稀释真信息）。
- 发现记忆矛盾时，以最新交互/用户明示为准，并标注矛盾来源。
